# 0015 -- 2Q / SLRU: two thin exports, the splits, the ghost, iteration, stats, D15

Status: accepted (S7 -- the simplest scan-resistant baseline members)

## Context

S7 adds the classic, well-understood scan/one-hit filters that sit BETWEEN classic
LRU and the modern trio (SIEVE / S3-FIFO / W-TinyLFU): a segmented probation ->
protected design. They are the honest baseline for the benchmark story ("here is the
textbook scan-resistant one; here is what SIEVE / S3-FIFO / W-TinyLFU buy over it").
Both ride the SAME `SlotStore` substrate (decisions/0011) via the shared `newStore`
factory: default Map backing, opt-in `keys:'int'` strict-zero backing, the same
`[lite-lru]`-tagged int-key door, the conservation invariant, the onEvict fire-after
+ `_inOnEvict` reentrancy guard (decisions/0002), TTL (decisions/0017), zero-GC
iteration (decisions/0018), and opt-in stats (decisions/0019).

## The decision -- D15

### D15.1 -- TWO thin named exports (`Slru`, `TwoQ`), NOT one member with a mode flag

Two tiny named exports over the shared substrate, NOT a single member carrying a
`mode` flag. A flag would add a branch to EVERY hot `get`/`put` (probation-vs-A1in,
promote-vs-no-promote) -- bytes in a hot body that never pay for themselves, and a
polymorphic hot path where the family law (law 7) wants each one monomorphic. Two
exports keep each hot path a single straight line AND keep the tree-shake clean:
`import { Slru }` drops `TwoQ`'s body and vice versa (single main file +
`sideEffects:false` + named exports -- the same file-shape ruling as
Sieve/S3Fifo/WTinyLfu). No new file; both are named exports in `Lru.js`.

### D15.2 -- the splits (frozen in the constructor)

`Slru` (Segmented LRU): a probation FIFO + a protected LRU.

```
protectedCap = Math.round(capacity * 0.8);   // 80% protected, ~20% probation
```

Newcomers enter probation (FIFO). A probation entry is PROMOTED to protected on its
SECOND hit (see D15 promote rule below). Protected is an LRU capped at
`protectedCap`; a promotion that overflows protected DEMOTES protected's LRU tail
back to probation's MRU. probation is NOT hard-capped -- its residents are
`size - protectedSize`; the total is bounded by `capacity` via eviction. The eviction
victim is ALWAYS the probation tail (oldest), or -- only when probation is empty --
the protected tail. Because eviction prefers probation, a scan of distinct one-hit
keys (which never earn a second hit) churns through probation and NEVER evicts a
protected entry. Degenerate caps: `capacity 1/2` give `protectedCap == capacity`
(probation transiently holds newcomers, eviction still works); the impl and oracle
agree on the edge.

`TwoQ` (the full 2Q, Johnson & Shasha VLDB'94): an A1in FIFO + an Am LRU + a fixed
A1out ghost of keys evicted from A1in.

```
a1inCap  = Math.max(1, Math.round(capacity * 0.25));  // 25% admission FIFO
amCap    = capacity - a1inCap;                          // informational; Am not hard-capped
ghostCap = amCap;                                       // A1out ghost bound (D15.3)
```

Newcomers enter A1in (FIFO) UNLESS the key is currently in the A1out ghost -- a
second sighting of a recently-A1in-evicted key -- in which case it is admitted
straight to Am and consumed from the ghost. An A1in hit does NOTHING (no promotion --
A1in is a pure FIFO probation queue); an Am hit moves the entry to Am's MRU (LRU
behaviour). The ONLY path into Am is via the ghost (A1in -> evicted -> A1out -> seen
again -> Am), which is exactly 2Q's design. At capacity one reclaim step frees a slot:
if A1in is at/over its target (`a1inSize > a1inCap`) OR Am is empty, evict the A1in
tail and record its key in the ghost; otherwise evict the Am LRU tail (Am evictions
are NOT ghosted, mirroring S3-FIFO's MAIN). A distinct one-hit-wonder flood churns
through A1in only, so it never evicts an Am entry -- scan resistance.

### D15.3 -- the A1out ghost bound (fixed ring, KEYS only, never values)

The ghost is bounded at construction to `ghostCap` and holds KEYS only, NEVER values
(retention hygiene). It reuses the S3-FIFO `_gRing` pattern verbatim (decisions/0013):

  - `keys:'int'` -> STRICT zero-alloc: a fixed open-addressed Int32 membership table
    (state byte + backward-shift deletion, no tombstones) PLUS a power-of-two Int32
    FIFO ring (masked indices). Both sized once, never grown.
  - default Map backing -> a `Set` membership + an `Array` FIFO ring. Honestly
    AMORTIZED (a `Set` resize can allocate -- the D3/D11 caveat, restated).

Bounding the ghost at construction is load-bearing: an UNBOUNDED ghost would let
`_gLen` grow without limit and drift the T7 conservation invariant. `capacity 1`
gives `ghostCap == 0` (no ghost -- A1in-only churn, like S3-FIFO's degenerate edge).
A key re-admitted to Am is consumed from the ghost via an in-place ring shift (COLD:
never on the sequential-key hot path). `delete`/`_reap`/`clear` never touch the ghost
except `clear`, which empties it (a delete/reap is not an eviction, so it is never
ghosted -- mirrors S3-FIFO).

The promote rule (Slru), pinned. A newcomer enters probation UNVISITED. The FIRST
hit sets a per-slot `_vis` bit and does NOT reorder (probation is FIFO). The SECOND
hit clears the bit and PROMOTES the entry to protected (MRU). So `get(X)` once leaves
X in probation; `get(X)` twice moves X to protected. A `put(update)` counts as a hit
for this rule (an update is a write, like a hit). `has`/`peek` are neutral (no `_vis`
change, no promotion). This is exactly the "promote on 2nd hit" law; a variant that
promotes on the FIRST hit is the t9 `slru-promote-on-first-hit` control and MUST
diverge from the oracle. `TwoQ` needs no `_vis` bit (A1in never promotes internally;
Am promotion is via the ghost path only).

### D15.4 -- iteration order (decisions/0018, D18.1)

Pinned per member: PROTECTED / Am FIRST, then PROBATION / A1in, each MRU..LRU. NOT a
global recency order -- two segments concatenated (like S3-FIFO MAIN-then-SMALL and
W-TinyLFU window-then-protected-then-probation). The keys-only A1out ghost is
EXCLUDED (it holds no resident entry).

  - `Slru._iterHeads()` -> `[_protHead, _probHead]`.
  - `TwoQ._iterHeads()` -> `[_amHead, _a1Head]`.

### D15.5 -- stats counting (decisions/0019, D19.2)

Uniformly OUTCOME-based, exactly like the rest of the family:

  - `get()` drives hits/misses AFTER the lookup resolves (a live hit -> `hits++`; an
    absent OR stale-TTL key -> `misses++`).
  - `has()`/`peek()` are hit/miss-NEUTRAL.
  - `put()` drives `puts++` AFTER the store mutation lands (a throwing put counts
    nothing), and drives exactly ONE `evictions++` per REAL capacity victim.
  - a stale-TTL `get()` is a miss AND an eviction (the `_reap` site).

SEGMENT MOVEMENT IS NOT AN EVICTION. `Slru`'s probation->protected promotion and its
protected->probation demotion, and `TwoQ`'s A1in->Am admission, are internal
relinks, NOT evictions -- they are never counted (mirrors S3-FIFO graduation and
W-TinyLFU window->probation demotion). The ghost recording an A1in-evicted key is
part of the ONE real eviction already counted, not a second event.

## Consequences

  - Two new named exports (`Slru`, `TwoQ`) implementing the SAME `LiteCache<K,V>`
    surface (get/put/has/peek/delete/clear + purgeStale + stats/resetStats +
    keys/values/entries + size/capacity), so `new LiteLru(n)` swaps for `new Slru(n)`
    or `new TwoQ(n)` and stays type-checked. The dts-drift counted surface is 14 per
    class, identical to the other four members. The export set grows by two.
  - One `_seg` Uint8 column per member (0/1: probation/protected, A1in/Am), plus a
    `_vis` Uint8 column on `Slru` for the 2nd-hit rule. `TwoQ` adds the S3-FIFO ghost
    columns. All fixed at construction, never grown (gated by t6 Gate SLRU / TWOQ:
    the backing byteLengths are invariant across a >= 60000-op churn, and
    `_gLen <= _ghostCap` always).
  - `validate()` gains `Slru`/`TwoQ` descriptors (protected+probation / Am+A1in), the
    `_seg <= 1` range check, the segment-sum term, and (TwoQ) the `_gLen <= ghostCap`
    ghost bound.
  - Scan resistance is a NAMED, gated law: t2 proves a cap-sized distinct-key scan
    evicts 0 protected/Am entries; t9 controls (`slru-promote-on-first-hit`,
    `twoq-unbounded-ghost`) each diverge/drift and MUST fail.
  - The public API is additive; VERSION stays "1.5.0" (moves only at /release; the
    1.6.0 target is written into CHANGELOG/README/llms.txt prose only this session).
