# 0026 -- LruK: the eleventh member, LRU-K (K=2) recency-of-recency, D26

Status: accepted (S19 -- the classic recency-of-recency member; the K-th-backward-distance
policy with a 0-link-write warm hit and a provably non-exceedable 5-link-write promotion)

## Context

S19 adds `LruK` as the eleventh `LiteCache<K,V>` family member: LRU-K (O'Neil, O'Neil &
Weikum, SIGMOD'93), fixed at K=2 (the canonical, best-studied setting -- "LRU-2"). LRU-K was
the original recency-of-recency policy: it evicts by the K-th BACKWARD DISTANCE -- the time of
a page's K-th-most-recent reference -- so a page must prove itself with >= K references before
it is protected. `Lirs` (decisions/0023) and `ClockPro` (decisions/0025) are later, more
elaborate takes on the same recency-of-recency idea; `LruK` ships the direct, historically
first mechanism, which is a genuinely different substrate exercise: two Float64 reference-time
columns and a min-scan victim rule, not a stack, a clock or a frequency ladder.

It rides the SAME `SlotStore` substrate (decisions/0011) via the shared `newStore` factory:
default Map backing, opt-in `keys:'int'` strict-zero backing, the `[lite-lru]`-tagged int-key
door, the conservation invariant, the onEvict fire-after + `_inOnEvict` reentrancy guard
(decisions/0002), TTL (decisions/0017), zero-GC iteration (decisions/0018), opt-in stats
(decisions/0019) and snapshot/restore (decisions/0021). No new file; `LruK` is a named export
in `Lru.js`.

## The decision -- D26

### D26.1 -- K is fixed at 2 (no knob, no CRP-K matrix)

K=2 is fixed. LRU-2 captures essentially all of LRU-K's measured benefit in the literature
while keeping the state a caller must reason about to exactly two timestamps per page. A knob
`K` would make every hot path carry a variable-length history walk per key (K stamps to slide
on each reference) and would fork the victim rule -- neither is worth it for a micro-library
whose headline is a fixed, byte-countable hot body. This is a deliberate deviation from the
paper's general-K formulation; it does not change LRU-2's eviction behavior.

### D26.2 -- two Float64 reference-time columns; the write budget

Per-slot state is:
  - `_r0` (Float64): the most-recent reference timestamp.
  - `_r1` (Float64): the SECOND-most-recent reference timestamp (the K=2 backward distance).
  - `_st` (Uint8): bit0 = warm (>= K references). Cold = < K references.

Both columns are member-specific, allocated WITH the store, fixed and never grown -- the other
members' hot paths stay byte-identical (like LIRS/ClockPro `_st`). They are NEVER a per-key
array; the "column allocated with the store" law holds.

A reference (get hit / put update) is `_r1[s] = _r0[s]; _r0[s] = ++_t` -- exactly 2 STAMPS.
  - a WARM hit does that and nothing else: 0 link writes (measured, `LRUK_WRITES_HIT_WARM`).
  - a COLD->WARM promotion additionally unlinks the slot from the cold list and pushes it to
    the warm list: up to 2 link writes for the detach (interior) + up to 3 for the head push =
    at most 5 (2..5), non-exceedable (measured, `LRUK_WRITES_HIT_PROMOTE` = the reachable
    maximum, 5). This is PROVABLY NON-EXCEEDABLE: the cold detach
    writes at most 2 array cells (each branch writes one cell OR a scalar head/tail field), the
    warm push writes at most 3 (`_prev[s]`, `_next[s]`, `_prev[warmHead]`); the head/tail
    scalar assignments are not link (`_next`/`_prev`) stores. `CountedLruK` pins the interior/
    non-empty-warm scenario at its maximum (5) and proves the never->5 ceiling holds over a
    churn window in t6.

### D26.3 -- the cold sentinel is -Infinity, not 0 ("null is not zero")

A cold page has only one reference, so its K=2 backward distance is INFINITE, and its stored
2nd-reference time `_r1` sits at the -Infinity SENTINEL. It is emphatically NOT "K-distance 0":
0 is a real, recent timestamp and would rank a cold page as freshly protected. -Infinity makes
a cold page rank for eviction FIRST under a `<`-min-`_r1` comparison, which is exactly the
two-phase victim rule (D26.5). `_r1` is initialized to -Infinity with the store, reset to
-Infinity on unlink/reap/evict, and validated to be the sentinel for every cold page on
restore. The monotone logical clock `_t` (a plain number field, Float64 semantics, exact to
2^53) is bumped `++_t` per reference so no two stamped timestamps collide -> the min-`_r1`
warm victim is always UNIQUE (the differential oracle relies on this).

### D26.4 -- bounded keys-only history, WARM re-admission (deviation from the paper)

The paper retains, for a "retained information period," the FULL reference history HIST(p) of
recently-evicted pages, so a returning page resumes with its real past reference times. This
member instead keeps a BOUNDED, KEYS-ONLY non-resident history (`LruKHistory extends ArcGhost`,
cap = capacity, drop-oldest -- the same ring as Lirs/ClockPro). Every eviction records the
victim key; a put of a key still in the history re-admits the page directly as WARM at
`_r1 = _r0 = ++_t` (it has demonstrably been referenced >= K times over its lifetime, so it
skips the cold probation). delete/reap are NOT recorded (a removal keeps no metadata, like the
rest of the family).

OWNER-RULING DEVIATION. This is a bounded approximation of the paper's unbounded, timestamped
HIST(p): (1) the history is keys-only, cap = capacity, drop-oldest, so a page evicted long ago
is forgotten; (2) a re-admitted page resumes at a synthetic recent K-distance (`r1 = r0 = t`)
rather than its true historical 2nd-reference time. This trades some fidelity for a strict
memory bound and zero per-key allocation, matching Lirs D23 and ClockPro D25.2. It changes the
re-admission STAMP, not the resident-set victim RULE; the classic no-CRP LRU-2 eviction order
among resident pages is preserved and is what the differential oracle checks.

### D26.5 -- the victim rule: cold tail O(1), else linear min-`_r1` warm scan

Resident pages live in TWO disjoint intrusive lists over the SHARED `_next`/`_prev` columns
(a slot is in exactly one): the COLD list (`_coldHead` newest .. `_coldTail` oldest) and the
WARM list (`_warmHead` .. `_warmTail`). Because they partition the resident set over the
shared columns, validate()/iteration/snapshot reuse the shared machinery unchanged.

Eviction:
  1. if a cold page exists, evict the COLD TAIL -- O(1). Cold pages have infinite backward
     K-distance and go first; among them the subsidiary order is LRU (a cold page is never
     re-referenced while cold -- a re-reference promotes it -- so the cold list is FIFO by
     insertion, which is also LRU), so the oldest cold page is the tail.
  2. else, LINEAR-scan the warm list for the smallest `_r1` (the largest K-distance).

HONESTY (this is the ClockPro-attempt lesson). The warm scan is O(size) READS, O(1) writes.
It is NOT amortized O(1) and NO constant miss+evict bound is claimed: an all-warm steady state
scans the entire warm list on every eviction. t6 MEASURES the worst-observed scan length on a
dedicated all-warm stream and pins a per-stream regression TRIPWIRE (`LRUK_EVICT_SCAN_TRIPWIRE`)
-- a tripwire, never a bound -- and confirms the single worst-case op stays under the 4 ms
pause budget. The state O(size) worst case is documented, not hidden.

### D26.6 -- no correlated-reference period (CRP)

The paper's CRP suppresses double-counting bursts of references that are part of one logical
access (so a page read twice in quick succession is not spuriously promoted). This member has
NO CRP: the 2nd reference always promotes cold->warm. A CRP would add a per-reference clock
comparison and a tunable window to every hot path, contradicting the fixed, byte-countable hot
body (D26.1). Documented deviation; it can only make a page promote SOONER than the CRP model,
never change the resident victim rule.

### D26.7 -- snapshot captures the reference times, the clock and the history

`dump()` captures the warm + cold lists (values/expiry via the shared `snapList`), their
aligned `_r0`/`_r1` columns, the logical clock `_t` (as `tick`, since `snapBase` owns `t` =
capture time), and the bounded history (keys only, oldest..newest). Dropping the reference
times, the clock or the history is a fail-OPEN future-eviction bug, so all are captured and
`restore()` fails CLOSED on: any tag/shape mismatch; a malformed/short/mis-aligned reference
column; a non-finite `_r0` (or an `_r1` that is neither finite nor the -Infinity sentinel); a
cold page whose `_r1` is not the sentinel; a `tick` that is not a non-negative finite number;
or a history over its bound. The t9 controls (`lruk-drop-r1`, `lruk-lru-tiebreak`) prove the
round-trip and the victim rule have teeth.

DOCUMENTED LIMITATION, not a bug: a snapshot containing COLD pages is NOT plain-JSON
round-trippable. A cold page's `_r1` is captured as the `-Infinity` sentinel (D26.3), and
`JSON.stringify` silently degrades `-Infinity` to `null`. `restore()` then fails CLOSED on that
column with a numeric-column error (the same door that rejects any malformed reference-time
column above) rather than silently admitting a corrupt cold page. `structuredClone` (which
preserves `-Infinity` exactly) round-trips a COLD-page snapshot fine; only the JSON path is
affected, and only when the snapshot has at least one cold resident.

## Consequences

- A new named export `LruK` + `LruKHistory` (internal) in `Lru.js`; a `LruK` type in
  `Lru.d.ts`; a `makeLruKOracle` differential oracle; harness wiring (`wrapLruK`,
  `lrukPolicy`/`lrukIntPolicy`/`lrukTtlPolicy`, `CountedLruK`, the write constants and the scan
  tripwire, `SNAP_MEMBERS`); t0/t2/t5/t6/t7/t9 coverage; validate term 15; the perf gate, the
  bench roster and the demo counts; README + llms.txt roster/API/counts.
- The family is now eleven members under one surface. The zero-GC laws hold: the warm hit is
  0-link-write + 2-stamp + zero-alloc; the cold->warm promotion is a fixed 5-link-write + 2-stamp
  + zero-alloc; the reference columns are preallocated with the store; the history is a bounded
  preallocated ring. The one HONEST non-constant is the min-`_r1` warm scan -- measured, pinned
  by a per-stream tripwire, never claimed as a bound.
