# 0028 -- Car: the thirteenth member, CAR (Clock with Adaptive Replacement), D28

Status: accepted (S21 -- the CLOCK reformulation of ARC; completes the CLOCK-approximation trio;
the family is FINAL at thirteen -- CART is DEFERRED, see below). The honest ruling: CAR's HIT is a
genuine 0-link-write / exactly-1-`_st`-store reference-bit set, but its EVICTION carries NO pinned
constant miss+evict bound -- it is amortized O(1) / worst-case O(capacity), exactly like ClockPro.

## Context

S21 adds `Car` as the thirteenth `LiteCache<K,V>` family member: CAR, Clock with Adaptive
Replacement (Bansal & Modha, "CAR: Clock with Adaptive Replacement", USENIX FAST'04). CAR is the
CLOCK reformulation of ARC (decisions/0016): it keeps ARC's EXACT semantics -- a RECENT list T1 and
a FREQUENT list T2, two keys-only ghosts B1 (evicted-from-T1) and B2 (evicted-from-T2), and a single
adaptive integer `p` (the target size of T1, 0..c) with NO knobs -- but realizes T1/T2 as reference-
bit CLOCKS instead of ARC's LRU lists. The payoff is the same one SIEVE/S3-FIFO/ClockPro earn: a HIT
sets ONE reference bit and MOVES NOTHING, where ARC relinks the hit entry to the T2 MRU on every
access. CAR is the sibling of `ClockPro` (decisions/0025, the CLOCK approximation of LIRS): together
with SIEVE they complete the CLOCK-approximation trio -- SIEVE (a CLOCK-ish lazy FIFO), ClockPro
(CLOCK approximating LIRS's recency-of-recency), and CAR (CLOCK reformulating ARC's recency/frequency
adaptation). Patent status was checked and is CLEARED.

It rides the SAME `SlotStore` substrate (decisions/0011) via the shared `newStore` factory: default
Map backing, opt-in `keys:'int'` strict-zero backing, the `[lite-lru]`-tagged int-key door, the
conservation invariant, the onEvict fire-after + `_inOnEvict` reentrancy guard (decisions/0002), TTL
(decisions/0017), zero-GC iteration (decisions/0018), opt-in stats (decisions/0019) and snapshot/
restore (decisions/0021). No new file; a new named export in `Lru.js` (the tree-shake moat holds).

## Decision

### D28.1 -- two reference-bit clocks on the shared columns, two hands, a 2-bit `_st`

T1 (recent) and T2 (frequent) are each a circular CLOCK, realized -- exactly like ClockPro's single
clock -- as a NIL-terminated doubly-linked list threaded through the shared `_next`/`_prev` columns
(`_headTx` = newest .. `_tailTx` = oldest) whose hand WRAPS (`_advance(_tail) -> _head`). The
traversal is circular (a clock has no ends); the NIL terminus lets the member reuse the family's
shared iteration (CacheIterator), conservation (validate's CAR term) and snapshot (snapList/snapLink)
machinery. A slot is in EXACTLY one clock. Per-slot state is a member-specific `_st` Uint8 column
(mirrors LIRS/ClockPro `_st`, NOT a field on the shared SlotStore -- the other members' hot paths
stay byte-identical): `CAR_REF` = bit0 (referenced), `CAR_T2` = bit1 (in the frequent clock). Two
Int32 hands `_hT1`/`_hT2` are the eviction/rotation position in each clock (NIL only when that clock
is empty).

### D28.2 -- two bounded keys-only ghosts B1/B2 (CarHistory extends ArcGhost)

B1 and B2 are `CarHistory extends ArcGhost` (the same open-addressed int ring / Set+array FIFO the
S3-FIFO/TwoQ/Arc/LIRS/ClockPro/LruK/Mq ghosts use). B1 is sized to `capacity` (|T1|+|B1| <= c), B2 to
`2*capacity` (|T2|+|B2| <= 2c). Drop-oldest at the bound; `consume(key)` removes a specific key on
re-admission. Keys ONLY, never values (retention hygiene -- proven by the t7 census).

### D28.3 -- the adaptive integer `p`, a B1 hit raises it, a B2 hit lowers it

`p` starts at 0. On a miss whose key is in B1 (a recent page evicted too soon):
`p = min(p + max(1, floor(|B2|/|B1|)), c)`. On a miss whose key is in B2 (a frequent page evicted too
soon): `p = max(p - max(1, floor(|B1|/|B2|)), 0)`. The ghost sizes are read BEFORE the key is
consumed (mirrors Arc D16.3). A ghost re-admit (B1 or B2) re-enters T2 with ref 0. A true miss enters
T1 with ref 0. The t9 `car-no-adapt` control freezes `p` and MUST diverge from the oracle.

### D28.4 -- REPLACE: hand rotation with a second chance; fixed-capacity honesty

`_replace()` frees exactly one resident and returns its slot for in-place reuse. From the T1 hand
when `|T1| >= max(1, p)` (defensively total: fall back to the non-empty clock), else the T2 hand: a
REFERENCED page has its reference bit CLEARED and earns a second chance -- a T1 survivor MIGRATES to
the T2 MRU (it proved worthy of the frequent clock), a T2 survivor rotates within T2 (the hand
advances). The first UNREFERENCED page found is the victim, demoted to B1 (from T1) or B2 (from T2).
The ghost directory is then trimmed to the bounds (drop B1 LRU when |T1|+|B1|==c, else drop B2 LRU
when the directory total is 2c) -- and the SAME trim runs below capacity (delete-induced) before a
new non-ghost T1 entry grows the directory. Fixed-capacity honesty (restating Arc D16.2 / ClockPro
D25.4): the RESIDENT value capacity is EXACTLY `capacity`; only the T1/T2 split adapts, |T1|+|T2| ==
size. The evicted victim ALWAYS had reference bit 0 (the eviction branch fires only on `(_st[h] &
CAR_REF) === 0`).

### D28.5 -- the HIT is a genuine 0-link-write, exactly-1-`_st`-store reference-bit set

`get` and `put`-update do exactly `_st[s] |= CAR_REF` -- 0 `_next`/`_prev` writes, exactly 1 `_st`
store, regardless of which clock the page is in. This is the Sieve/S3-FIFO/ClockPro headline and the
whole point of CAR over ARC (ARC relinks to the T2 MRU on every hit). `CountedCar` pins it as a gate
(`CAR_WRITES_HIT_LINKS = 0`, `CAR_WRITES_HIT_ST = 1`), measured in torture t6 and the perf gate.

### D28.6 -- the HONEST no-constant-bound ruling (the recurring ClockPro S18 cautionary tale)

CAR's EVICTION is NOT a constant. `_replace()` rotates the hands and can clear MANY reference bits in
a single miss: on a full-scan-then-insert (fill to capacity, reference every resident page, then
insert), REPLACE must clear/migrate the whole clock before it finds an unreferenced victim -- and a
T1 survivor migration is real list surgery (a detach + a push). So the miss+evict is AMORTIZED O(1)
(classic CLOCK -- each reference bit is cleared at most once per full sweep) but WORST-CASE
O(capacity) `_st` + link writes, EXACTLY like ClockPro (decisions/0025, D25.5). We do NOT claim any
CONSTANT miss+evict bound (unlike `Lfu`'s PROVEN <= 14 or `Mq`'s PROVEN non-exceedable <= 33). The
t6 `carStream` worst-observed scan length is a per-STREAM regression TRIPWIRE on that corpus, not a
cap; it makes NO claim about the true worst case. This is the SAME honesty discipline that got a
false "hard bound" REJECTED for ClockPro (the S18 cautionary tale): a false constant that is really
O(capacity) is a lie, so it is stated as amortized O(1) / worst-case O(capacity) everywhere (code
comments, this decision, llms.txt, GUIDE.md, README.md).

CRITICAL ATTRIBUTION: the reference-bit CLEARS done inside `_replace()` are NOT counted into the hit-
path write budget. `CountedCar` attributes writes PER CALL SITE -- the HIT path (`get`/`put`-update)
touches only `_st[s] |= CAR_REF` (0 links + 1 `_st` store) and never calls `_replace`; the ref-bit
clears + migrations belong to the miss/evict path (a `put` of an absent key at capacity). The t6 gate
resets the counters immediately before a lone hit to isolate the hit cost, and measures miss+evict
writes on a separate `put(miss)` with a fresh reset -- the two budgets never contaminate each other.
Getting this attribution right is what makes the 0-link-write hit gate true rather than a lie.

### D28.7 -- iteration order, snapshot, conservation

Iteration walks T2 (frequent, MRU..LRU) THEN T1 (recent, MRU..LRU) -- mirrors Arc D16.5 -- resident
only, the keys-only B1/B2 ghosts EXCLUDED. `dump()` (tag `m:'Car'`) captures the T2/T1 clocks
(values/expiry), each page's `_st` byte, the two hands, `p`, and both ghosts verbatim; `restore()`
fails closed on any tag/shape mismatch, an `_st` byte that is not a valid 2-bit tag or whose inT2 bit
disagrees with its clock, a `p` out of [0,c], a hand that does not reference a resident slot of its
clock, or a ghost that breaks a bound. Dropping the hands, `p` or the reference bits is a fail-OPEN
future-eviction bug -- the t9 `car-p-dropped` / `car-ref-bits-dropped` round-trip controls catch it.
The validate CAR term asserts: |T1|+|T2| == size; every `_st` byte in {0..3}; the inT2 bit agrees
with the clock; `p` in [0,c]; both hands NIL iff their clock is empty else resident; |T1|+|B1| <= c;
the directory total |T1|+|T2|+|B1|+|B2| <= 2c; and a key is in EXACTLY one of T1/T2/B1/B2 (a resident
key is in T1 xor T2 by the CAR_T2 bit; a ghost key is consumed on re-admit).

## CART DEFERRED -- the family is FINAL at thirteen

CART (CAR with Temporal filtering, the second algorithm in the same FAST'04 paper) is DEFERRED and
the family is declared FINAL at thirteen members. CART's only substantive delta from CAR is its
admission rule -- whether a re-referenced page enters T1 or T2 is gated by a per-page "long-term
reuse" (temporal-filter) bit, a TUNING refinement of CAR's placement, not a distinct mental model.
CAR already delivers the headline this family exists to demonstrate (ARC's exact adaptive semantics
with a 0-link-write CLOCK hit); CART would add a second near-identical adaptive-CLOCK member whose
"which do I pick" answer is "CART is a slightly better-filtered CAR" -- a poor return against the
one-mental-model-per-member bar the roster holds. Should a measured workload ever show CART's filter
decisively beating CAR on real traces (via the bench + Belady OPT tool), it can be reconsidered; the
default is that the CLOCK-approximation trio (SIEVE / ClockPro / CAR) is complete and the family is
closed at thirteen.

## Consequences

- A thirteenth member, one new named export; the tree-shake moat and the uniform surface hold.
- CAR is the CHEAPEST-hot-path adaptive member: ARC's recency/frequency self-tuning with a
  0-link-write hit. Reach for it over `Arc` when the hit-path write cost matters, and over `ClockPro`
  when you want ARC's recency/frequency adaptation rather than LIRS's recency-of-recency.
- The honest cost is stated everywhere: hit 0 links + 1 `_st` store; miss+evict amortized O(1),
  worst-case O(capacity), NO pinned constant bound (the carStream number is a tripwire).
- Proven by the full torture suite (t0 laws, t2 adversarial + phase-change p law, t5 100k
  differential vs an INDEPENDENT oracle on both backings + ttl, t6 Gate CAR strict zero-alloc +
  writes-per-hit + carStream tripwire, t7 soak + census, t9 car-no-adapt / car-p-dropped /
  car-ref-bits-dropped controls), the node:test boundary suite (test/Car.test.js), the perf gate
  (SCENARIOS 26), the bench, and the demo. VERSION was unchanged at implementation time (1.14.0);
