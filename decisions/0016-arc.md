# 0016 -- ARC: one adaptive member, two ghosts, an adaptive `p`, D16

Status: accepted (S8 -- the no-tuning adaptive baseline; the member that stresses the laws)

## Context

S8 adds ARC (Megiddo & Modha, FAST'03 -- "Adaptive Replacement Cache", patent
expired), the gold-standard self-tuning baseline. ARC splits the resident set into
a RECENT list T1 (seen once) and a FREQUENT list T2 (seen 2+), and drives the split
with a single integer target `p` that ADAPTS between recency- and frequency-friendly
phases on its own -- no knobs. Two GHOST lists (B1 = keys evicted from T1, B2 = keys
evicted from T2) supply the signal that moves `p`.

ARC is the member the ROADMAP flags as stressing the laws: the ghost lists roughly
double the key-index metadata, and `p` moves the effective recency/frequency split at
runtime -- in tension with law 3 (fixed, load-bearing capacity). This decision owns
that tension up front.

It rides the SAME `SlotStore` substrate (decisions/0011) via the shared `newStore`
factory: default Map backing, opt-in `keys:'int'` strict-zero backing, the same
`[lite-lru]`-tagged int-key door, the conservation invariant, the onEvict fire-after
+ `_inOnEvict` reentrancy guard (decisions/0002), TTL (decisions/0017), zero-GC
iteration (decisions/0018), and opt-in stats (decisions/0019). The two ghosts reuse
the S3-FIFO/TwoQ `_gRing` pattern (decisions/0013, 0015): keys only, NEVER values,
bounded rings sized once at construction.

## The decision -- D16

### D16.1 -- ONE `Arc` named export, no sibling, no mode flag

A single `Arc` named export over the shared substrate. NOT a member carrying a
`mode` flag (recency-mode vs frequency-mode): a flag would add a branch to EVERY hot
`get`/`put`, bytes in a hot body that never pay for themselves, and a polymorphic hot
path where the family law (law 7) wants each one monomorphic. ARC is ALREADY adaptive
-- the `p` split is the "mode" and it self-tunes -- so there is nothing a flag would
select that the algorithm does not select for you. One export keeps each hot path a
single straight line AND keeps the tree-shake clean (single main file +
`sideEffects:false` + named exports -- the file-shape ruling shared with
Sieve/S3Fifo/WTinyLfu/Slru/TwoQ). No new file; `Arc` is a named export in `Lru.js`.

### D16.2 -- fixed-capacity honesty; the ghost bounds

The RESIDENT value capacity stays EXACTLY `capacity` (`c`). `|T1| + |T2| <= c`, and
`== c` whenever full; a new resident is admitted ONLY after a resident is evicted
(the fixed-capacity law is honored in letter). What ADAPTS is `p` (the T1 target
size, `0 <= p <= c`) -- the recency/frequency SPLIT, never the total resident count.

The ghosts are bounded typed-array rings, fixed at construction, never grown. Two
invariants are maintained and asserted by `validate()`:

```
|T1| + |B1| <= c        (the recency directory L1 never exceeds capacity)
|B1| + |B2| <= c        (the combined ghost directory never exceeds capacity)
```

From these, `|B1| <= c` and `|B2| <= c`, so each ghost ring is sized to hold `c`
keys (a power-of-two Int32 ring on `keys:'int'`, an Array ring on the Map backing) --
sized ONCE, never grown. The combined-ghost budget is `c` (a bounded-ARC realization,
the steady-state property of classic ARC where, when resident is full, the two
directory halves sum to `2c` so the two ghost halves sum to `<= c`). `p` is a single
integer field that never allocates.

### D16.3 -- the `p` adaptation rule (the self-tuning signal)

A miss whose key is found in a ghost is the adaptation signal, applied on `put` (the
op that brings a value in). Using the ghost sizes AT the moment of the hit (the hit
key still counted in its ghost, so the divisor is >= 1):

```
key in B1 (recency ghost):  p = min(p + max(1, floor(|B2| / |B1|)), c)   // favor recency
key in B2 (frequency ghost): p = max(p - max(1, floor(|B1| / |B2|)), 0)  // favor frequency
```

A B1 hit means "I evicted a RECENT page too soon" -> grow T1's target `p`. A B2 hit
means "I evicted a FREQUENT page too soon" -> shrink `p`. The direction is
load-bearing and pinned by the phase-change law (t0/t2) and the `arc-p-frozen`
control (t9), which MUST fail that law. A `get` never touches the ghosts (ghost
interaction is a cold `put`-only path, mirroring TwoQ/S3-FIFO), so the get hot path
carries no ghost branch.

### D16.4 -- REPLACE(x, p): the victim selection, boundary included

Bringing a new resident in at capacity evicts exactly one resident to a ghost:

```
REPLACE(xInB2):
  if |T1| >= 1 and (|T1| > p  OR  (xInB2 and |T1| == p)):
      evict T1 LRU  -> its key to B1 MRU
  else:
      evict T2 LRU  -> its key to B2 MRU
```

The BOUNDARY case `|T1| == p` with the incoming key in B2 tips the choice toward
evicting T1 (so the just-proven-frequent key re-entering T2 is favored). Defensive
totality (get/put are split and `delete` exists, unlike textbook single-access ARC):
if the chosen list is empty, evict the other -- REPLACE always frees a resident when
one exists. A true miss and a B1 hit pass `xInB2 = false`; a B2 hit passes `true`.

The degenerate `|T1| == c` (T2 empty, all resident in T1, B1 empty) true-miss is a
DIRECT eviction of the T1 LRU with NO ghost record (classic ARC Case IV-A else) --
`pushT1` would otherwise overflow `|T1| + |B1|`. And a Case-IV true miss that would
make `|T1| + |B1| == c` drops the B1 LRU first (classic ARC Case IV-A) to keep the L1
bound.

### D16.5 -- iteration order (decisions/0018, D18.1)

`Arc._iterHeads()` -> `[_t2Head, _t1Head]`: T2 (frequent) FIRST, then T1 (recent),
each MRU..LRU. Two segments concatenated -- NOT a global recency order (mirrors
S3-FIFO MAIN-then-SMALL, W-TinyLFU window-then-protected-then-probation, Slru
protected-then-probation, TwoQ Am-then-A1in). The keys-only ghosts B1/B2 are
EXCLUDED (they hold no resident entry).

### D16.6 -- stats counting (decisions/0019, D19.2)

Uniformly OUTCOME-based, exactly like the rest of the family:

  - `get()` drives hits/misses AFTER the lookup resolves (a live hit -> `hits++`; an
    absent OR stale-TTL key -> `misses++`).
  - `has()`/`peek()` are hit/miss-NEUTRAL.
  - `put()` drives `puts++` AFTER the store mutation lands, and drives exactly ONE
    `evictions++` per REAL capacity victim (the one resident REPLACE -- or the
    direct T1 evict -- removes when resident was full).
  - a stale-TTL `get()` is a miss AND an eviction (the `_reap` site).

GHOST MOVES AND `p` ADAPTATION ARE NOT EVICTIONS. Moving a key T1->B1 or T2->B2 is
part of the ONE real eviction already counted; dropping a ghost LRU to respect a
bound, consuming a ghost key on re-admission, and every `p += / p -=` are internal
bookkeeping, never counted (mirrors S3-FIFO graduation, W-TinyLFU demotion, Slru
promotion, TwoQ ghost recording). A `get`/`put` on a T1 resident that PROMOTES it to
T2 (ARC promotes any hit to frequent) is a relink, not an eviction.

## Consequences

  - One new named export (`Arc`) implementing the SAME `LiteCache<K,V>` surface
    (get/put/has/peek/delete/clear + purgeStale + stats/resetStats +
    keys/values/entries + size/capacity), so `new LiteLru(n)` swaps for
    `new Arc(n)` and stays type-checked. The dts-drift counted surface is 14 per
    class, identical to the other six members. The export set grows by one (6 -> 7).
  - One `_seg` Uint8 column (0 = T1, 1 = T2) so `_detach` fixes the correct list,
    plus the two bounded ghosts. All fixed at construction, never grown (gated by t6
    Gate ARC: the backing byteLengths are invariant across a >= 60000-op mixed
    churn, `_b1Len + _b2Len <= c`, `_t1Size + _b1Len <= c`).
  - `validate()` gains an `Arc` descriptor (T2 + T1 lists), the `_seg <= 1` range
    check, the segment-sum term, and the two ghost-bound terms.
  - Adaptivity is a NAMED, gated law: t0/t2 prove `p` moves the RIGHT way across a
    recency phase then a frequency phase; t9 controls (`arc-p-frozen`,
    `arc-unbounded-ghost`) each diverge/drift and MUST fail.
  - The public API is additive; VERSION stays "1.6.0" (moves only at /release; the
    1.7.0 target is written into CHANGELOG/README/llms.txt prose only this session).
